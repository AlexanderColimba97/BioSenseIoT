## 🚨 NON-NEGOTIABLE RULES

### Rule 1: Authentication Model (CRITICAL)

#### ✅ CORRECT MODEL:
```
Users       → JWT (email:password) → AccessToken (1h) + RefreshToken (24h)
Devices     → Device JWT (deviceId:deviceSecret) → DeviceToken (12h)
                ↓
            NEVER mix these two!
```

#### ❌ FORBIDDEN:
- `X-BioSense-Key` header (API key antipattern)
- Using user JWT for devices (auth confusion)
- Using device JWT for users (auth confusion)
- Hardcoded API keys anywhere
- Bearer tokens without proper JWT validation

#### 🔍 ENFORCEMENT:
When reviewing code, ask:
1. Is this a USER auth or DEVICE auth?
2. Does it use correct JWT type?
3. Are claims properly set (type, sub, aud, iss, exp)?
4. Is comparison timing-safe?

### Rule 2: Device Flow (MANDATORY SEQUENCE)

#### ✅ CORRECT FLOW:

```
STEP 1: User Authentication
────────────────────────────
POST /api/v2/auth/login
├─ Email + Password
├─ Response: AccessToken (1h) + RefreshToken (24h)
└─ Claims: { sub: email, type: "user", aud: "biosense-users" }

STEP 2: Device Registration
─────────────────────────────
POST /api/v2/devices/register
├─ Header: Authorization: Bearer AccessToken (user JWT)
├─ Backend: Create Device + generate deviceSecret
├─ DB: INSERT devices table
└─ Response: { deviceId, deviceSecret }

STEP 3: BLE Provisioning
──────────────────────────
Mobile App → BLE → ESP32
├─ Encrypted payload
├─ Data: WiFi SSID, WiFi Password, deviceId, deviceSecret
└─ ESP32: NVS storage (encrypted)

STEP 4: Device Activation
──────────────────────────
POST /devices/activate
├─ Body: { deviceId, deviceSecret }
├─ Auth: Timing-safe comparison (NOT standard JWT yet)
├─ Backend: Validate + generate Device JWT
├─ Response: { token: "device.jwt.token" }
└─ ESP32: Memory storage (temporary)

STEP 5: Sensor Data Transmission
─────────────────────────────────
POST /api/v2/sensors/reading
├─ Header: Authorization: Bearer deviceToken (Device JWT)
├─ Body: { macAddress, deviceId, mq4, mq7, mq135, readingId, timestamp }
├─ Backend: Validate JWT + schema + UNIQUE(reading_id)
├─ Response: 200 OK or 409 CONFLICT
└─ Repeat every 10 seconds
```

#### ❌ WRONG FLOWS TO REJECT:

```
❌ WRONG: Device using user JWT
POST /api/v2/sensors/reading
├─ Authorization: Bearer <userJWT>  ← NO! Use device JWT
└─ Reason: Wrong authentication context

❌ WRONG: Getting deviceId from request body
POST /api/v2/sensors/reading
├─ Body: { deviceId: "attacker-device-id", ... }  ← NO! Extract from JWT
└─ Reason: deviceId must come from JWT (sub claim), not request

❌ WRONG: No deduplication
POST /api/v2/sensors/reading
├─ No readingId field
├─ No UNIQUE constraint
└─ Reason: Allows duplicate data

❌ WRONG: Activating without deviceSecret
POST /devices/activate
├─ Only sending deviceId
└─ Reason: No authentication, anyone can activate any device
```

### Rule 4: Clean Architecture (MANDATORY)

#### ✅ CORRECT LAYERING:

```
Controllers (Presentation)
    ├─ Only: Route mapping, request binding, response formatting
    ├─ NO: Business logic, data access, calculations
    └─ Example: @PostMapping, validate input, call service

            ↓

Services (Application/Use Cases)
    ├─ Only: Business logic, orchestration, use case execution
    ├─ NO: HTTP details, database queries, external calls
    └─ Example: Validate business rules, check permissions, coordinate

            ↓

Repositories (Infrastructure/Data Access)
    ├─ Only: Database operations, queries, persistence
    ├─ NO: Business rules, authentication, calculations
    └─ Example: findByDeviceId(), save(), delete()
```

#### ❌ VIOLATIONS TO REJECT:

```java
// ❌ WRONG: Business logic in controller
@PostMapping("/sensors/reading")
public Mono<ResponseEntity<>> save(@RequestBody SensorReadingDTO dto) {
    // Business logic in controller ← WRONG!

        // Risk calculation
    }
    return sensorRepository.save(reading);

    public RiskLevel calculateRisk(SensorReading reading) {

    }

    return sensorService.processSensorReading(dto);
```

### Rule 5: Security (CRITICAL)

#### ✅ SECURITY CHECKLIST:

```
Authentication:
  ✅ JWT tokens signed (HMAC-SHA256 minimum)
  ✅ Expiration set and validated
  ✅ Timing-safe comparison for secrets
  ✅ No API keys (use JWT exclusively)
  ✅ User JWT ≠ Device JWT (different claims)

Authorization:
  ✅ Every endpoint validates auth
  ✅ deviceId from JWT, not request body
  ✅ User can only access own devices
  ✅ Device can only write own readings
  ✅ 403 Forbidden for unauthorized access

Encryption:
  ✅ HTTPS/TLS 1.2+ for ALL external communication
  ✅ Passwords hashed (bcrypt, 12 rounds)
  ✅ Secrets in environment variables
  ✅ No plaintext in logs
  ✅ No hardcoded values

Input Validation:
  ✅ All inputs validated (types, ranges)
  ✅ Prepared statements (no SQL injection)
  ✅ JSON schema validation
  ✅ Size limits on uploads

Rate Limiting:
  ✅ Per IP: 1000 req/hour
  ✅ Per user: 500 req/hour
  ✅ Per device: 100 readings/hour
  ✅ Response: HTTP 429 when exceeded
```

#### ❌ SECURITY VIOLATIONS TO REJECT:

```
❌ API Keys exposed: X-BioSense-Key in headers
❌ Secrets hardcoded: private static final String KEY = "secret"
❌ Plaintext auth: Authorization: Basic email:password
❌ Mixed auth: User JWT used for device endpoints
❌ No validation: Accept any deviceId without verification
❌ Timing attacks: String password1.equals(password2)
❌ No HTTPS: HTTP endpoints for sensitive operations
❌ SQL injection: String query = "SELECT * FROM users WHERE id = " + id
```

## 🔴 RED FLAGS (IMMEDIATE REJECTION)

These violations are deal-breakers. **ALWAYS reject**:

```
1. API key authentication (X-BioSense-Key, apiKey header)
   → Refactor to JWT immediately

2. User JWT used for device authentication
   → Create separate device JWT flow

3. deviceId from request body (not JWT)
   → Extract from JWT token claims

4. No readingId deduplication
   → Add UNIQUE constraint + generator

5. Business logic in controller
   → Extract to service layer

6. Hardcoded secrets
   → Move to environment variables

7. HTTP for sensitive operations
   → Require HTTPS

8. No authorization checks
   → Add @Secured or manual validation

9. String comparison for secrets
   → Use timing-safe comparison

10. No input validation
    → Add @Valid + schema validation
```

## 🎓 EXAMPLES: Correct vs Wrong

### Example 1: Sensor Reading Endpoint

#### ❌ WRONG (Reject this):
```java
@PostMapping("/api/v2/sensors/reading")
public ResponseEntity<> save(@RequestBody SensorReadingDTO dto) {
    // ❌ No auth validation
    // ❌ deviceId from request body
    // ❌ No deduplication
    SensorReading reading = new SensorReading();
    reading.setDeviceId(dto.getDeviceId());  // ← WRONG!
    reading.setMq4(dto.getMq4());
    reading.setMq7(dto.getMq7());
    reading.setMq135(dto.getMq135());
    sensorRepository.save(reading);
    return ResponseEntity.ok("Saved");
}
```

**Violations:**
1. No JWT validation
2. deviceId from request (attacker could send fake deviceId)
3. No readingId deduplication
4. No input validation (MQ values could be negative)
5. Business logic in controller

#### ✅ CORRECT (Approve this):
```java
@PostMapping("/api/v2/sensors/reading")
@Secured("ROLE_DEVICE")
public Mono<ResponseEntity<SensorReadingResponse>> save(
    @RequestHeader("Authorization") String authHeader,
    @RequestBody @Valid SensorReadingDTO dto
) {
    return jwtAdapter.validateDeviceToken(authHeader)
        .flatMap(deviceId -> {
            // ✅ deviceId from JWT, not request
            return sensorService.processSensorReading(deviceId, dto);
        })
        .map(ResponseEntity::ok)
        .onErrorResume(e -> Mono.just(
            ResponseEntity.status(401).build()
        ));
}

@Service
public class SensorService {
    public Mono<SensorReading> processSensorReading(String deviceId, SensorReadingDTO dto) {
        // ✅ Business logic in service
        
        // ✅ Validate input
        if (!isValidRange(dto.getMq4())) {
            return Mono.error(new ValidationException("MQ4 out of range"));
        }
        
        // ✅ Generate unique readingId
        String readingId = UUID.randomUUID().toString();
        
        // ✅ Check deduplication
        return sensorRepository.existsByReadingId(readingId)
            .flatMap(exists -> {
                if (exists) {
                    return Mono.error(new DuplicateException());
                }
                
                SensorReading reading = SensorReading.builder()
                    .deviceId(deviceId)  // ← From JWT
                    .readingId(readingId)
                    .mq4(dto.getMq4())
                    .mq7(dto.getMq7())
                    .mq135(dto.getMq135())
                    .timestamp(Instant.now())
                    .build();
                
                return sensorRepository.save(reading);
            });
    }
}
```

**What's correct:**
1. JWT validation on request
2. deviceId extracted from token
3. Input validation (ranges)
4. readingId generation and dedup
5. Business logic in service
6. Proper error handling
7. Immutable creation pattern
