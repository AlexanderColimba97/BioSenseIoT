# AUTH Token Persistence Fix - Testing Guide

## Problem Solved
✅ Fresh user registration → sync button was failing with "Tu sesión expiró" error immediately after registering
✅ Device was never reaching database due to auth token not being available
✅ Root cause: `localStorage` not persisting TOKEN_EXPIRY in Capacitor (mobile), causing `isTokenExpired()` to incorrectly mark token as expired

## Solution Applied
1. **Enhanced `isTokenExpired()` with intelligent fallback:**
   - If token exists but TOKEN_EXPIRY missing → check when token was stored
   - If stored < 30 min ago → assume token is still valid (1 hour expiry)
   - Only mark as expired if truly over time limit

2. **Improved `storeTokens()` with verification:**
   - Added `TOKEN_STORED_AT` timestamp for fallback detection
   - Added console logging to verify successful storage
   - Added error handling for localStorage failures

3. **Better error messages for debugging:**
   - All auth errors logged with `[Auth]` prefix for console tracking
   - Device linking errors logged with `[Device]` prefix

## Testing Steps (After deploying frontend code)

### Step 1: Test Fresh Registration
1. Open app and clear all data (Settings > App > Clear Cache)
2. Go to login screen
3. Switch to "Regístrate" (Register)
4. Fill in:
   - Email: `testuser123@example.com` (or new test email)
   - Password: `Test1234!`
   - Nombre: `Test User`
5. Click "Registrarse"
6. **Expected:** Should succeed and show main app screen

### Step 2: Monitor Console Logs
Open DevTools (F12 on desktop, or mobile debugger):
- Look for: `[Auth] Tokens guardados exitosamente` ✅
- If found: tokens were saved to localStorage correctly
- If warning shows: `[Auth] ⚠️ Warning: Token no se guardó en localStorage!` then localStorage is broken

### Step 3: Test Sync Button Immediately After Registration
1. After successful registration (no delay)
2. Go to Sync Device section (or relevant area)
3. Click "Sincronizar" button
4. **Expected outcomes:**
   - If tokens saved correctly → should NOT show "Tu sesión expiró" error
   - Should proceed to ask for device/WiFi credentials
   - Device should register in Railway database

### Step 4: Console Logs for Debugging
Check console for these messages:
```
✅ SUCCESS patterns:
[Auth] Tokens guardados exitosamente
[Auth] Usando token con fallback de tiempo        // fallback used when TOKEN_EXPIRY missing
[Auth] Token refrescado exitosamente
[Device] Vinculando dispositivo: {...}
[Device] Device linking successful

❌ ERROR patterns:
[Auth] ⚠️ Warning: Token no se guardó en localStorage!  // localStorage failed
[Auth] Error al guardar tokens: ...                    // storage error
[Auth] Error refrescando token: ...                    // refresh endpoint failed
[Device] Error 401: Token inválido o expirado         // JWT validation failed
```

### Step 5: Verify Device Registration in Railway
1. Go to Railway dashboard
2. Select BioSenseIoT project
3. Check database → Devices table
4. Should see new device with:
   - `macAddress`: from ESP32
   - `name`: from registration
   - `user_id`: linked to registered user
   - `api_secret`: generated by backend

## If Test Fails

### Case 1: "Tu sesión expiró" appears immediately
**Diagnosis:**
- Check console for storage errors
- Verify JWT_SECRET environment variable in Railway

**Fix:**
```bash
# In Railway environment variables:
JWT_SECRET=<your-secret-key-here>
```

### Case 2: localStorage shows as not saved
**Diagnosis:**
- Capacitor Storage might be failing
- May need to use Capacitor Storage API instead of localStorage

**What to check:**
- Open DevTools → Application → Local Storage
- Should see:
  - `ACCESS_TOKEN`: <jwt-token>
  - `REFRESH_TOKEN`: <jwt-token>
  - `TOKEN_EXPIRY`: <timestamp>
  - `TOKEN_STORED_AT`: <timestamp>

### Case 3: 401 error from /api/v2/devices/link
**Diagnosis:**
- Backend JWT validation failing
- JWT_SECRET mismatch between frontend token generation and backend validation

**Verification:**
- Check Railway logs for JWT validation errors
- Verify JWT_SECRET is set and same as used in token generation

### Case 4: Device not showing in database
**Diagnosis:**
- Request reached backend but device repository failed
- Or network timeout before reaching backend

**Check:**
- Railway database connection
- Device repository implementation in LinkDeviceUseCase
