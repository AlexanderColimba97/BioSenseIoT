                            5 PROBLEMAS RESUELTOS

🔴 ANTES: Crashes WiFi (`assert failed: udp_new_ip_type`)
🟢 AHORA: Strict WiFi verification - Sin crashes
   Solución: if (WiFi.status() != CONNECTED) return false;

🔴 ANTES: Vinculación de usuario confusa (sin estado claro)
🟢 AHORA: STATUS_UNCONFIGURED + LED naranja parpadeando
   Solución: Máquina de 3 estados explícitos

🔴 ANTES: BLE desperdiciando radio en producción
🟢 AHORA: BLEDevice::deinit() automático tras vinculación
   Solución: BLE solo en STATUS_UNCONFIGURED

🔴 ANTES: Payload JSON incompleto
🟢 AHORA: Siempre incluye macAddress + readingId + mq4/mq7/mq135
   Solución: JSON validator en sendReading()

🔴 ANTES: Loop bloqueante (delays congelando ESP32)
🟢 AHORA: Non-blocking state machine con timers millis()
   Solución: handleStateUnconfigured/Warmup/Operational()

================================================================================
                          ARQUITECTURA v3 (3 ESTADOS)
================================================================================

STATUS_UNCONFIGURED
├─ BLE Active + Listening
├─ LED Orange Blinking (500ms on/off)
├─ Wait for credentials via BLE
└─ No sensor reading until bound

STATUS_WARMUP
├─ WiFi Connecting (non-blocking)
├─ BLE Deinitialized (radio freed)
├─ LED Green Pulsing
├─ NTP Sync for timestamps
├─ 30-second sensor warmup
└─ No data sending (warming up)

STATUS_OPERATIONAL
├─ WiFi Connected ✓
├─ Strict WiFi verification every loop
├─ Read sensors every 10 seconds
├─ LED dynamic (Red/Orange/Green = risk indicator)
├─ Send to backend with Bearer auth
└─ Deduplication with readingId

================================================================================
                           PUNTOS CLAVE (5)
================================================================================

1️⃣ STRICT WiFi VERIFICATION
   • Check WiFi.status() en cada send
   • Si NO conectado → return false (sin reintentos inseguros)
   • Previene crash UDP

2️⃣ MÁQUINA DE 3 ESTADOS
   • UNCONFIGURED: Esperando credenciales (BLE active)
   • WARMUP: WiFi conectando + sensores calientando (30s)
   • OPERATIONAL: Leyendo y enviando datos (10s interval)

3️⃣ BLE DEINIT AUTOMÁTICO
   • BLE solo activo en UNCONFIGURED
   • BLEDevice::deinit(true) al transicionar a WARMUP
   • Libera radio, menos interferencia WiFi

4️⃣ PAYLOAD SEGURO SIEMPRE
   • Authorization: Bearer [apiSecret]
   • JSON: macAddress + readingId + mq4 + mq7 + mq135 + timestamp
   • Deduplicación por readingId

5️⃣ NON-BLOCKING TIMERS
   • Usa millis() no delay()
   • Loop siempre ejecutándose
   • handleStateUnconfigured/Warmup/Operational() específicas
